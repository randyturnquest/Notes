How Authorization with Identity Pools is Handled?
    1. The web app or mobile app sends its authentication token to Cognito Identity Pools. The token can come from a valid Identity Provider. 
    2. CIP exchanges the user authentication token for temporary AWS credentials to access resources such as S3 or DynamoDB. 
    3. AWS credentials are sent back to the user. 
    4. The temporary AWS crednetials will be used to access AWS resources.

AWS CodeDeploy - Deployment Configurations: 
- A set of rules and conditions that you can tweak to instruct CodeDeploy on how aggressive or conversative your deployment approach is going to be. 

On the AWS Console, when you click on CodeDeploy > Deployment configurations, you will a list of... AWS-defined deployment strategies that you can use for your deployments. You can also create your own deployment configuratiosn if you want. 

CodeDeployDefault.OneAtATime:
- This is the slowest deployment. 
- This will take time to deploy on all instances but the application will remain online since only once instance is offline at any given time.

CodeDeployDefault.Linear10PercentEvery10Minutes:
- Deployment for Lambda functions. This deployment will use Aliases on the backend to shift traffic from old version to the new version. 
- 10% of traffic will be shited to the newer version every 10 minutes. Deployment will run at 10-minute intervals until 100% of the traffic is shifted to the newer version. 

CodeDeploy manages each deployment stage as a collection of lifecycle event hooks through an... AppSpec file. 
- Written in JSON or YAML

Example for CodeDeploy's AppSpec file:
- You may instruct CodeDeploy to install dependencies that your application requires before installing the new applicaiton version, or you can tell CodeDeploy to alter some file permissions before starting the deployment. 

YAML is the only available format for configuring AppSpec in EC2/On-premise. 

Lifecycle Event Hooks - Stages:
    - Start
    - ApplicationStop
    - DownloadBundle
    - BeforeInstall
    - Install
    - AfterInstall
    - ApplicationStart
    - ValidateService
    - End

Lifecycle Event Hooks - Start: 
    - Initiates the instance for deployment

Lifecycle Event hooks - ApplicationStop: 
    - Used for running any scripts that will prepare your instance in receiving the new application version. 
    - If you're deploying a new application, v2 you can include a script that will disable the pervious v1 version

Lifecycle Event Hooks - Download Bundle:
    - CodeDeploy will pull the new version "v2", from a source repository into the instance, as the name implies. 
    - Triggered automatically following the ApplicationStop event. 

Lifecycle Event Hooks - BeforeInstall:
    - If you want to backup the configuration files of yout old application or any old logs and stop them elsewhere in your disk. So they are not overwriiten when the new application is copied. 

Lifecycle Event Hooks - Install:
    - CodeDeploy copies your new application files to the new destination that you specified. 

Lifecycle Event Hooks - AfterInstall:
    - Can be used to decode database string information, application credentials and perhaps other encrypted data that you've sent down as part of your application bundle and move everything to its proper destination.
