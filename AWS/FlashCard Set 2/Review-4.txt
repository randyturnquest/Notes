Step Machine States - Task State: 
    - Represents a single unit of work in your State Machine

Step Machine States - Choice State 
    - Adds a branching logic to your workflow

Step Machine States - Pass State
    - Moves input from the previous state to its output without performing work. 

Output Filters - Result Path
    - Used to include the original input to the state's output
    - Only Task, Map, Parallel, and Pass states are supported.

Blue/Green Deployment
    Blue Env (Old Version) - Refers to the environment to which current user traffic is directed.
    Green Env (New Version)- Where the latest application version is deployed
        - After the new version has been deployed and tested, you can shift traffic away to this environment

Although written in JSON or YAML, .ebextensions file extensions must always be .config
    - Place at root level of folder (Elastic Beanstalk won't recognize them)

Two Lifecycle Rules Available
    - Set the application version limit by total count
    - Set the application versions limit by age
        - Any versions older than the value you put here will be deleted once you upload a new version.  
    - Rentention Option: Choose to keep the source bundle of your application version in Amazon S3. if yes, Elastic Beanstalk will still delete the application version from its record, but the version's source code will remain in Amazon S3

Amazon Simple Queue Service (SQS) - Standard supports best-effort ordering meaning
    - the messages received in the queue can sometimes be in a different sequence than the one in which they were sent. 

In terms of throughput, the Standard queue beats FIFO queue by a large margin. Standard queues can handle an unlimited number of transactions (TPS) per API action. 
    - FIFO queues can only support up to 3000 messages per API. 

SQS Concepts - Polling
    - The method by which SQS retrieves messages from the queue and sends them to the requesting consumer

SQS Concepts - Short Polling
    - Default with ReceiveMessage request searches only a subset of the SQS servers to find messages to include in the response. 

SQS Short Polling is best for
    - time sensitive applications for branch applications that can send another query if it received an empty response previously
    - To enable set your wait time to 0

SQS Long Polling:
    - ReceiveMessage request searches all of the SQS servers for messages. SQS returns a response after it collects at least one available message, up to the number of messages specified in the request, and will only return an empty response if the rolling wait time expires. 

SNS - Application-to-Application Messaging
    - This allows for seamless messaging  between different applications using AWS endpoints like Lambda functions, SQS queues, and HTTP/S endpoints. 

SNS - Message Durability - Dead Letter Queue:
    - Ensures undelivered messages are preserved and managed appropriately.
