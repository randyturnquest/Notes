Git Merge
+++++++++

Branching makes it easy to work within self-contained contexts, but often we want to incorporate changes from one branch into another. 

git merge
    - We merge branches, not specific commits
    - We always merge to the current HEAD branch

git switch main
git merge bugfix

1. Switch to or checkout the branch you want to merge the changes into. 
    - The receiving branch
2. Use the git merge command to merge changes from a specific branch into the current branch.

+++++++++
Fast Forward Merge
+++++++++

When there's nothing on the main branch that's been committed and the branch being worked on is merged to that branch after a few extra commits. 

All we do is catch up the main branch. (Fast Forward)
    - It transfers the work history that was on the bigfix branch. 

+++++++++
Merge Commits
+++++++++

What happens when we try to merge a branch to main when main has more data we don't have on our branch. 
    - Rahter than performing a simple fast foward, git performs a "merge commit". 
    - We end up with a new commit on the main branch. 
        - Git will prompt us for a commit message. 
Depending on the specific changes you are trying to merge, Git may not be able to automatically merge. This results in merge conflicts, which you need to manually resolve. 

When you encounter a merge conflict, Git warns you in the console that it could not automatically merge. 

>> CONFLICT(content): Merge conflict in example.txt
>> Automatic merge failed; fix conflicts and when commit the result.

+++++++++
Resolving conflicts
+++++++++

Steps to resolve merge conflicts:

1. Oopen the file(s) with merge conflicts
2. Edit the file(s) to remove the conflicts. Decide which branch's content you want to keep in each conflict. Or keep the content from both. 
3. Remove the conflict "markers" in the document
4. Add your changes and then make a commit.
