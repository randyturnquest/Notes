    - Path may need to be added in VS Code

Amending Commits
+++++++++

Rather than making a brand new separate commit, you can "redo" the previous commit using the --amend option.

git commit --amend

Replace the tip of the current branch by creating a new commit. The recorded tree is prepared as usual (including the effect of it -i and -o options and explicit pathspec), and the message from the original commit is used as the starting point, instead of an empty message, when no other message is specified from the command line via options such as -m, -F, -c, etc. The new commit has the same parents and author as the current one (the --reset-atuhor option can countermand this).

Git Ignore
+++++++++

Ignoring Files

We can tell Git which files and directories to ignore in a given respository using a .gitignore file.
    - This is useful for files you NEVER want to be commited, including:
        - Secrets, API keys, Credentials
        - Operating System Files (.DS_Store on Mac)
        - Log Files
        - Dependencies & Packages

.gitignore

Create a file called .gitignore in the root of the repository. Inside the file, we can write patterns to tell Git which files & folders to ignore:
    - .DS_Store will ignore files named .DS_Store
    - folderName/ will ignore an entire directory
    - *.log will ignore any files with the .log extension.

Node Modules do not need to be tracked through Git. 

+++++++++
Annotated Tag
+++++++++

git tag -a <name of tag>

Page opens in VSCode and you write your annotated tag.
Using git tag -a to create a new annotated tag. Git will then open your default text editor and prompt you for additional information. 

Similar to git commit, we can also use the -m option to pass a message directly and forgo the opening of the text editor. 

git tag -show <tag>: To see the annotated Tag
Annotated Tags shows the "tagger", the tag data and message.

Tagging Previous Commits
+++++++++

git tag -a <tagname> <commit-hash>: We can tag an older commit by providing the commit hash. 

Forcing Tags
+++++++++

git tag -f: Allows us to force our tag or resuses a tag that is already referring to another commit. 
    - react > git log --oneline
    - react > git tag v17.0.3 696e736be
    - fatal: tag 'v17.0.3' already exists
    - react > git log --oneline
    - react > tag v17.0.3 696e736be -f
    - Updated tag 'v17.0.3' (was 07027f93e)

Deleting Tags
+++++++++
git tag -d <tagname>

Pushing Tags
+++++++++

By default, the git push command doesn't transfer tags to remote servers. If you have a lot of tags that you want to push up at once, you can use the --tags option to the git push command. This will transate all of your tags to the remote server that are not already there. 

git push origin <tagname>: Pushes a specific tag to the remote branch
git push origin --tags: Pushes all tags up to the remote branch
